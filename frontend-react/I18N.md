# Internationalization (i18n) System

Complete i18n implementation supporting 7 languages with automatic browser detection, persistent preferences, and RTL layout support.

## Supported Languages

| Code    | Name              | Status |
|---------|-------------------|--------|
| `en`    | English           | ✅     |
| `zh-CN` | 中文（简体）       | ✅     |
| `ja`    | 日本語             | ✅     |
| `ko`    | 한국어             | ✅     |
| `es`    | Español           | ✅     |
| `fr`    | Français          | ✅     |
| `de`    | Deutsch           | ✅     |

## Quick Start

### Basic Usage

```tsx
import { useI18n } from '@/i18n';

function MyComponent() {
  const { t } = useI18n();
  
  return (
    <div>
      <h1>{t('navigation.dashboard')}</h1>
      <button>{t('common.save')}</button>
    </div>
  );
}
```

### With Interpolation

```tsx
const { t } = useI18n();
t('common.x_minutes_ago', { count: 5 });
// Output: "5 min ago" (en) / "5 분 전" (ko)
```

### Change Language Programmatically

```tsx
const { changeLanguage } = useI18n();
await changeLanguage('ja');
```

### Language Switcher Component

```tsx
import { LanguageSwitcher } from '@/components/LanguageSwitcher';

// In your header/sidebar:
<LanguageSwitcher showFlag />
```

## Formatting Utilities

### Date Formatting

```tsx
const { formatDate, formatTime, formatDateTime, formatRelativeTime } = useI18n();

formatDate(new Date());           // "Dec 15, 2024"
formatTime(new Date());           // "14:30"
formatDateTime(new Date());       // "Dec 15, 2024, 14:30"
formatRelativeTime('2024-12-14'); // "1 day ago"
```

### Number & Currency Formatting

```tsx
const { formatNumber, formatCurrency, formatPercent } = useI18n();

formatNumber(1234567.89);              // "1,234,567.89" (en)
formatCurrency(99.99, 'USD');          // "$99.99" (en) / "99,99 €" (de)
formatPercent(0.856);                  // "85.6%"
formatFileSize(1048576);               // "1 MB"
```

## Translation Keys

### Common Keys (`common.*`)
- Actions: `save`, `cancel`, `delete`, `edit`, `create`, `add`, `remove`
- States: `loading`, `saving`, `saved`
- Confirmations: `confirm_delete`, `confirm_cancel`
- Errors: `error`, `warning`, `success`, `info`, `not_found`, `unauthorized`

### Navigation Keys (`navigation.*`)
- Sections: `dashboard`, `chat`, `agents`, `projects`, `settings`
- Sub-pages: `users`, `teams`, `billing`, `integrations`, `plugins`

### Feature Keys
- `home.*` - Dashboard/home page
- `chat.*` - Chat interface
- `agents.*` - Agent management
- `projects.*` - Project management
- `settings.*` - Settings pages
- `auth.*` - Authentication
- `file_manager.*` - File management
- `analytics.*` - Analytics dashboard
- `user_menu.*` - User menu items

## Backend i18n

The backend (`app/i18n.py`) provides gettext-based translation support:

```python
from app.i18n import translate, ngettext, get_language_from_header

# Translate a string
translated = translate("Hello", language="ja")

# Plural forms
message = ngettext("1 item", "{n} items", count, language="de")

# Detect language from Accept-Language header
lang = get_language_from_header(request.headers.get("accept-language"))
```

### FastAPI Middleware

```python
from app.middleware.i18n import I18nMiddleware

app.add_middleware(I18nMiddleware)

@app.get("/api/data")
async def get_data(request: Request):
    lang = request.state.language
    return {"message": translate("Data loaded", language=lang)}
```

## Language Detection Priority

1. **URL Query Parameter**: `?lang=ja`
2. **Local Storage**: User's saved preference
3. **Browser Language**: `navigator.language`
4. **Fallback**: English (`en`)

## Adding a New Language

1. Create a new locale file:
   ```bash
   cp public/locales/en.json public/locales/ar.json
   ```

2. Update `config.ts`:
   ```typescript
   import arTranslation from '../../public/locales/ar.json';
   
   // Add to supportedLanguages
   { code: 'ar', name: 'العربية', flag: '🇸🇦', rtl: true },
   
   // Add to resources
   'ar': { translation: arTranslation },
   ```

3. Check completeness:
   ```bash
   npm run i18n:check
   ```

4. If RTL, ensure styles in `styles/rtl.css` handle the new language.

## Scripts

| Command | Description |
|---------|-------------|
| `npm run i18n:check` | Check translation completeness |
| `npm run i18n:extract` | Extract translation keys from code |
| `npm run i18n:add-language` | Add a new language template |

## Best Practices

1. **Use meaningful keys**: `agents.create_agent` not `agents.ca`
2. **Group by feature**: Keep related keys together
3. **Avoid concatenation**: Use interpolation (`{{count}}`) instead of string concatenation
4. **Context matters**: Use keys that describe the context, not the text
5. **Test all languages**: After adding new text, verify all language files are updated

## Type Safety

The i18n system provides TypeScript types for all translation keys:

```tsx
import type { RootJson } from '@/i18n';

// Type-safe key access
type HomeKey = keyof RootJson['home']; // "title" | "overview" | ...
```

## Browser Support

All modern browsers are supported. The `Intl` API is used for:
- `Intl.DateTimeFormat` - Date/time formatting
- `Intl.NumberFormat` - Number/currency formatting
- `Intl.RelativeTimeFormat` - Relative time ("2 hours ago")
- `Intl.PluralRules` - Plural form selection
- `Intl.DisplayNames` - Language/region names
